# Captured Agentiflow observation pages

Feature: `agentiflow.observation.pages.v1`. Local HTTP only. Existing whole-detail, events and board endpoints remain unchanged.

`GET /api/agentiflows/:id/snapshot?host=local[&refresh=true]` creates a finite **read-time observation**, not an atomic cross-file coordinator transaction. Reuses the same flow's capture for five seconds unless explicitly refreshed. The body carries `flow_id`, `host_id`, opaque `snapshot`, `source_generation` (captured metadata/log bytes, lead filenames, and the captured latest lead first-line bytes), `captured_at`, `expires_at`, the existing compact `record`, `definition`, `budget_state`, `latest_lead`, `board_journal`, and `sections` (units/events/board/leads totals). It carries no complete history arrays.

`GET /api/agentiflows/:id/snapshot/pages?host=local&snapshot=TOKEN&section=units|events|board|leads[&cursor=TOKEN][&limit=100]` returns exact owner, snapshot/generation/time, zero-based `offset`, `total`, `records`, opaque `next_cursor` or null, and observation `evidence`. Limit is 1–100, exact response <=1MiB. Start omits the cursor; next pages use only the returned cursor. Clients may retain earlier page cursors. HMAC authentication binds offset to the exact snapshot and section. Unknown query fields are rejected, not silently ignored.

Rows have `{id, source, value}`. Their IDs are stable **within this captured observation**, not cross-capture identities for board claim positions. Values:

- `units`: existing UnitDto; `source` is `children_ledger` or `legacy_unit`. The status output is null and `output_recorded_in_capture` flags inline captured output (false does not rule out a transcript answer). Fetch full outputs through the existing exact-unit output endpoint. Legacy codenames are explicitly derived; no unit transcript is read to decorate the list. Ledger rows supersede legacy rows for the same actual run ID. Ledger-backed unit values also carry `handle`, copied exactly from `ChildEntry.started.handle`, for the existing `/generated/:handle` lookup. The run ID is never substituted. Legacy units omit `handle`, including when a legacy record happens to contain an unsupported hint with that name.
- `events`: coordinator `events.jsonl` records only, source `coordinator`; ID preserves source line. It does not merge lead transcript speech or invent event timestamps.
- `leads`: `{round,path}`, source `lead_directory`, ascending round. Only the latest lead also has `prologue:{status,flow_id,host_id,path,run_start}`. `status=verified` contains the actual typed first RunStart event (`type`/`data`) from that exact anchored path, read with <=256KiB actual IO even when the remainder is huge. `missing`, `incomplete`, `malformed`, and `too_large` carry null `run_start`; malformed/oversized initial records are never skipped. The proof is bound to outer snapshot/source generation and exact flow/host/path. Historical paths remain handles requiring a finite transcript-page prologue. An advertised observation client must not fall back to whole-transcript reads if the bounded page endpoint is absent. Project identity is never inferred from a selected native session.
- `board`: existing typed claim/directive values and board post objects, sources `board_claim`, `board_directive`, `board_post`. Claims retain the captured-time expiration state. Board projection uses the existing tolerant fold over a private bounded mirror; `evidence.board_projection=legacy_tolerant` explicitly qualifies completeness. Posts are complete JSON object lines only.

Evidence includes read-time consistency, malformed JSON/ledger-record count, incomplete final-line count, captured input byte count, definition status (`loaded`, `missing`, `malformed`), project-scope verification requirement, coordinator-only event semantics, and on-demand unit outputs. Syntactically valid but semantically unusable legacy board records may still be skipped by the old projection. A zero malformed count is **not** a complete-board guarantee.

Captures read regular files into a private temporary mirror once, then discard the mirror after projecting retained rows. Reads and directory enumeration are anchored to an open run-directory descriptor, opened relative to the configured storage root with NOFOLLOW at every component. File reads check pre/post descriptor metadata and refuse changed files. Root/file replacements cannot redirect a capture to a symlink target. Each file is <=16MiB; record/definition/unit JSON <=256KiB; JSONL records <=256KiB; total captured source bytes <=32MiB; directory entries <=50,000; source records and retained rows <=100,000; the legacy board projection additionally limits <=4,000 journal/live-file records and <=256MiB of estimated reconciliation key work before folding; serialized retained data <=64MiB. The cache retains at most eight captures and 128MiB serialized data per AppState, with maximum ten-minute lifetime; eviction may expire a capture earlier. This bounds serialized data, not an exact RSS measurement. A separate one-permit capture gate bounds concurrent capture allocation; a busy capture returns429 without queuing blocking workers. Cache locks are brief and existing immutable pages remain readable during capture. No page rereads the source or walks transcripts. Capture reads only the latest lead's first line for identity proof; it does not read older lead contents or any unit transcript.

429 means another capture is in progress; retry this read later. 413 means a finite capture/page budget was exceeded; it never silently truncates into a complete result. 409 means source changed, owner/cursor mismatch, or expired/evicted snapshot; retain displayed data and offer explicit refresh. Remote host requests return501. Malformed primary record and duplicate lead-round handles return409. Missing run returns404. Errors do not cause automatic replay or mutation. Every endpoint is read-only; internal private temporary captures do not modify Rupu records.

Native integration must use this feature instead of simultaneously polling old full detail/events/board. Summary captures and frozen browsing windows are distinct: a new observation does not silently swap rows under the user's current selection. Show loaded/total, retained observation time, Earlier/More/Start, and explicit refresh. Use units' actual run identities and validate transcript/project scope before navigation. No native acceptance is claimed by backend tests.

Operator MCP exposes the same contracts as `agentiflows.snapshot` and `agentiflows.snapshot_pages`, with typed query schemas and read-only hints. The public read routes are not excluded from MCP parity. These operator tools remain distinct from a session’s runtime tool declaration.
