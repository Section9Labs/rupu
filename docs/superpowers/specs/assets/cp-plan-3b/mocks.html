Operator MCP · Plan 3b
Web UI for the Plan 3a capabilities: mocks for sign-off

Plan 3a gave the CP API and the MCP about 47 operations that until now only the CLI had (agentiflow launch, retry, continue, session stop and compact, skill installs, imports, cron, prune, accounts…). The spec says every one also gets web UI, designed for the human's task rather than mirroring the tool list, and every new or changed page is mocked and approved before it is built.

Every action goes on the page where its object already lives. Nothing gets a new top-level page; the only new places are a Library tab and two Settings tabs. Every destructive action previews or confirms first, and every write shows a pending state until the record actually changes, because a 202 means recorded, not done. The pieces marked MY CALL are placement choices I made; tell me which to change.

1 · Retry on a failed workflow run

/runs/:id

On a terminal run, the header gains Retry as the primary action, before Archive and Delete. It opens a small popover with the two choices a retry has. Retry resumes the run, so the mode defaults to the recorded one: a read-only run retries read-only, as on the CLI since #909. Afterwards the button turns into "Retry requested…" until the run's status flips to running.

2 · Continue a standalone agent run

/transcript?run=…

A finished or failed standalone run gets Continue. It opens the same composer the session page uses. The continuation keeps every flag of the original launch, so the composer only asks for what you'd change: a prompt (optional) and, under a disclosure, a different model or provider. It starts a new run and links to it.

/library?tab=skills

Library → Skills gets Install skills. Replacing an edited copy needs the force check, which is styled as danger. Each skill page gains Update and Validate.

8 · Query-language help

every ListQueryBar

A ? at the end of every query line opens the list's fields: key, kind and allowed values, with one example each. It is built from the same registry the server filters with, so a list can't advertise a field it doesn't take.
