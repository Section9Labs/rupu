# Exact reviewed network-ledger retention, v1

This is an additive, deliberately narrow contract. Existing archive policy execution and legacy prune stay distinct. `maintenance.retention.policy.v1` and its three `retention_execution_kinds` remain unchanged. Unix hosts additionally advertise `maintenance.retention.netflow_exact.v1`.

POST `/api/maintenance/retention/preview?host=local` accepts `kind: "netflow"` only with `authorization_mode: "exact_preview_set"`, explicit global and/or one registered project scope, and an optional positive age (default30d). Preview saves a durable operation record but deletes nothing. Existing writable/local gates apply. MCP uses the same existing explicit maintenance operations and destructive execution classification, with no additional runtime grants.

Eligibility is the intersection of recorded archive age and ledger modification time before the absolute captured cutoff. A candidate must be a per-run `netflow/<id>.jsonl` single-link regular file, with exact canonical archived standalone metadata and a retained regular archived transcript in the same selected root. Metadata must have the exact ID/version, `local_checkout` backend, absolute workspace, no session attribution, a parseable archive time, and a recorded PID positively reported dead (ESRCH only). Project-scoped metadata must name the selected registered root. Active transcript counterparts and canonical workflow run-store counterparts are refused. Shared `flows.jsonl`, orphan, unproven/remote worker, session, workflow, missing-PID, unsupported or ambiguous ledgers are retained. Current CLI worker attribution is supported only with a bounded (64 KiB), no-follow WorkerRecord proving exact ID/version, Cli kind, local_checkout capability, and current nonempty hostname, with no active node or configured/persisted host collision. Its exact digest is captured and rechecked; missing or changed proof keeps the file. Hostname is observational provenance, not unique machine identity: copied matching identities cannot be distinguished. This subset can legitimately be empty while other ledgers exist.

The configured global root is canonicalized before lease acquisition and checked against the captured policy. Policy roots retain device/inode identity and the exact registered-project file digest. Alias retarget, changed registration, symlinks and hard links fail closed. Receipt paths and hashes describe local retained artifacts; this protocol does not assert a cryptographic machine identity from imported metadata.

The receipt uses the existing schema/version, operation ID, preview ID, policy digest and owner identity, plus `authorization_mode: "exact_preview_set"`, `preview_selection: "exact_reviewed_candidate_set"` and a64hex SHA256 `preview_set_digest` of the immutable stored candidate manifest. Non-netflow receipts keep `policy_at_execution`, `observed_not_exact_candidate_authorization`, and a null set digest. Execute requires both exact digests, preview ID and matching mode. The preview expires after10minutes. The caller must not derive a token from its own candidate list.

POST `/api/maintenance/retention/operations/:id/execute` admits one execution through the existing cross-process lifecycle lease and durable journal. It uses only the stored reviewed set; no rescan or newly eligible candidate inclusion. Each group rechecks ownership metadata, positive process death, active counterparts, root and ledger stamp. Changed candidates are kept. Only ledger files are unlinked; transcript/ownership records are never execution artifacts. Single-file removal uses an opened no-follow parent and opened no-follow regular file with exact device/inode/size/mtime/ctime/link-count evidence.

The lifecycle lease coordinates supported archive/restore paths. Each ledger also uses a persistent no-follow `.leases/<filename>.lock`: writers, backfill and remote landing hold shared leases; preview/execution and legacy prune take a nonblocking exclusive lease. A busy or invalid lease keeps the ledger. The exclusive guard spans owner checks, durable dispatch, descriptor-relative unlink/fsync and durable outcome. Existing legacy prune remains a rescan, but now keeps busy, changed, symlink and hardlinked files explicitly rather than bypassing coordination.

Writer admission acquires before scheduling. The actual blocking open/write/flush closures own both the file and Arc lease, with file dropped first, so cancelling an async waiter cannot unlock queued filesystem work. RunNetflow retains the same guard continuously across final writer shutdown and queued blocking backfill. Remote landing creates a new temporary file and renames relative to the pinned directory; original aliases cannot redirect writes after acquisition. Persistent lock files are never removed. Lock order is lifecycle then one ledger; writers acquire only ledger coordination. Shared leases preserve existing multiple-writer behavior, not general writer serialization.

Non-Unix shared writers/backfill/landing retain path-backed behavior; exclusive guarded deletion is unsupported and unadvertised there. No Unix acquisition failure falls back to an unlocked write. Parent-relative checks and advisory leases are not atomic compare-and-unlink against arbitrary writers, old binaries, external process/filesystem races, or hostile mutation by the same local account. Session, workflow, remote and unattributed-orphan ledger eligibility is intentionally not inferred from the presence of writer coordination.

Durable dispatch is written before unlink, and outcome after unlink. A disconnect does not cancel admitted blocking work. Lost response or post-unlink journal failure remains unknown until exact GET receipt inspection; repeating execute never replays an admitted operation. Partial and unknown outcomes retain earlier confirmed effects and mark unattempted actions. No rollback, exactly-once server guarantee, or physical-space reclamation guarantee is claimed.

Existing bounds apply:256 candidate/kept groups,4096 artifact maximum (this subset has one per candidate),50,000 scanned directory entries,32MiB metadata and5second selection budget,4MiB manifest,8MiB journal,30second execution deadline. Overflow refuses preparation before any candidate is authorized. Reads return at most100rows/512KiB row payload and1MiB total reply, using operation/section/frontier-bound cursors. Ledgers are stamped, not decoded or copied into replies. Native Settings uses its existing journal, review and receipt pages and enables this kind only after positive capability evidence.

Disposable source fixtures cover exact-set/no-new-candidate execution, changed/replaced/active/linked paths, current CLI worker proof and foreign/unknown/live owners, mode/digest/expiration, post-unlink uncertainty and no replay, selected project rebinding, concurrent admission, route gates, shared/exclusive contention, alias/lock replacement, blocked landing/backfill, cancelled actual write and shutdown-to-queued-backfill lifetime. They are authored but unrun. No real cleanup, API request, service, credentials, build or test execution occurred in this source lane.
