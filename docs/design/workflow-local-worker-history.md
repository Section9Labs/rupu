# Local worker workflow history

Base a42e3beaa5736998fabcf9513976545044e326de. Read-only correction to project workflow history; no launch, restore, attach, remote request or new permission.

A nonempty `worker_id` is not a remote-host proof. CLI workflow invocation persists an exact local `WorkerRecord`, assigned worker in `run_envelope.json`, and the same worker/backend on `RunRecord`. Node mirrors instead pin `worker_id` to the registered remote node/host. The old blanket worker exclusion hid legitimate local CLI and Autoflow execution.

Feature `workflow.session_history.local_worker.v1` adds qualified local workers to the existing project history. No-worker records retain the previous behavior. Worker records require exact safe ID, supported typed registry record under this CP's global `autoflows/workers`, strict recorded hostname equality with the current OS hostname, and exact recorded envelope run/workflow/project/workspace-path/assigned-worker identity. Both envelope and run must record the supported `local_worktree` backend. A registered host/node identity collision always excludes a candidate, even with otherwise valid local proof; malformed host presence is not absence. Worker ID prefixes are never ownership proof.

Renamed/imported records whose hostname mismatches the current host, unknown hostnames, removed worker registries and incomplete legacy envelopes remain unavailable. They require their recorded owner route or explicit future migration; this reader never silently reassigns them. The current registry plus matching hostname is observational evidence, not a unique machine identity: a copied home retaining the same matching hostname and proof cannot be distinguished by this protocol. It does not reconstruct remote history or claim all local historical variants are supported.

Each admitted row adds `worker_id` (nullable) and `execution_origin`: `local_recorded` for unchanged no-worker records, `local_cli` or `local_autoflow` for qualified registry kinds. `local_recorded` describes the existing local-store route, not independently proven original execution location. Top-level `host_id:local` continues to identify the connected reader. Exact graph/transcript authorization and recorded-source handling are unchanged.

The response adds `ownership:{scope:project_records_before_query,excluded,unavailable,complete}`. These counts cover deduplicated exact-project records before literal/syntax filtering and pagination, not the number of matching omitted query results. A nonzero count means the result is not complete for all retained project records. No foreign-project names, raw registry data, inputs or credentials are emitted.

Proof reads use anchored no-follow regular files, capped at64KiB per worker record and256KiB per envelope,32MiB aggregate bytes,512 cached worker identities and4096 worker-qualified candidate attempts per request. Exhaustion yields unavailable counts rather than silently treating rows as valid. The pre-existing RunStore list/archived scan is unchanged and is not claimed bounded by these new proof limits. Active run identity wins before filtering as before; archive proofs are read from the archived run directory. Query grammar, ordering, limits and next_offset remain unchanged. Registry/envelope checks are observations, not a durable historical signature or filesystem transaction; current worker registration/hostname can make an older run unavailable.

Prepared source fixtures: CLI/Autoflow provenance, absent/corrupt/mismatched/imported proofs, registered remote identity collision, local-looking prefixes, no-worker compatibility, archive navigation identity and active precedence, metadata bounds and symlink refusal. No tests/builds or live calls were run in this isolated implementation. The retained incident was diagnosed by reading only whitelisted owner metadata; no real IDs or content are embedded in fixtures.
