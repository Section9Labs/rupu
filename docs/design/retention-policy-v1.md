# Retention policy v1 — implementation contract

Exact source base: `365bb3b09a8e9478d8daeb4c545c6a2dd91c1967`. Unix-only additive protocol; the legacy prune route, defaults and native preview remain available. No actual-store requests or deletions were used to implement this slice.

## Authorization and supported scope

Feature `maintenance.retention.policy.v1` and `retention_execution_kinds:[sessions,transcripts,cleanup]` are advertised on writable CP. Advertisement means this binary implements the protocol, not that a disk write is guaranteed to succeed. A successful persisted preview is required before execute. Netflow is rejected; its best-effort current live inventory is not destructive authorization.

Authorization is `policy_at_execution`: exact connected owner, selected roots and fixed absolute cutoffs, **not the preview candidate set**. New eligible archived resources may join the execution selection; resources restored or changed since preview may leave it. The executor selects once, completely within its bounds, then records that execution manifest before removal. No moving cutoff, second scan to discover more deletion targets, or automatic continuation occurs.

Scopes are explicit `{global:bool,project_id?:string}`; no filesystem path argument and no implicit startup/conversation project. At most one exact registered project. Sessions/cleanup require global=true. A project selects its existing canonical `.rupu` storage; a global alias is rejected with instructions to select global explicitly. Root identity and the bounded project registration digest are rechecked before selection and actions. Changing a registry, kind, scope or cutoff needs a fresh preview. Global storage configuration supplies omitted retention ages; both resolved UTC cutoffs are frozen in the policy. Negative/overflow ages reject.

The new executor deletes only declared archived artifacts. It retains active-location counterparts and auxiliary stream-only run directories; this is explicitly echoed by `policy.auxiliary_artifacts`. It does not claim full parity with the old prune's implicit auxiliary deletion. A session with foreign, active, duplicate or unproven transcript dependencies is kept as a whole. Known session schema/identity, completed run records, archive location and every present sidecar must agree. A present sidecar must match the exact run/session, have no worker owner, and have a positively dead PID—even when its JSONL is missing. Missing/unknown/live process evidence keeps it. Standalone candidates similarly require exact current metadata, no session/worker owner, recorded archival time, positively dead PID and no active counterpart. Project storage additionally requires matching recorded project root.

Session directory trees are captured into exact file entries and postorder directories. Symlinks, special files and ambiguous hard links reject the bounded selection. No `remove_dir_all` is used. Unknown directory contents created later prevent empty-directory removal; they are not recursively swept. Ownership artifacts carry hashes; data files carry identity/size/mtime/ctime stamps. These are current revision checks, not atomic inode CAS.

## HTTP and MCP

All endpoints require the directly connected local host and existing CP authentication.

- `POST /api/maintenance/retention/preview?host=local`: `{kind,scopes:{global,project_id?},older_than?}`. Persists a prepared operation and immutable preview; no resource deletion. Writable CP is required because this is an audit write. Returns summary envelope below.
- `POST /api/maintenance/retention/operations/:id/execute?host=local`: `{preview_id,policy_digest,authorization_mode:"policy_at_execution"}`. Acquires the lifecycle lease, validates exact intent and expiry, durably admits once, selects, and executes. Returns a terminal or observed receipt; a transport disconnect does not replay or cancel the admitted blocking task. Matching repeat requests return recorded state and never repeat accepted work. Mismatched intent is409. A prepared-but-never-admitted operation remains prepared after a pre-admission journal failure; clients still inspect its known ID rather than blind retry.
- `GET /api/maintenance/retention/operations/:id?host=local&section=summary|preview|effects&limit=100&cursor=...`: bounded read only; no retry, recovery mutation or deletion. Known operation IDs survive restart on the same physical owning root. Missing receipt/404 does not establish a prior remote attempt's outcome.

Tools: `maintenance.retention_preview` (audit-writing POST), `maintenance.retention_execute` (destructive), `maintenance.retention_operation` (read-only), with typed schemas and three additive inventory entries. The old `maintenance.prune` contract is unchanged.

Envelope: `schema_version:1`, `owner_host_id:"local"`, stable `owner_instance_id` (digest of canonical owning root identity), `operation_id`, `preview_id`, `policy_digest`, `policy`, `authorization_mode`, `preview_selection:"observed_not_exact_candidate_authorization"`, `state`, `recorded_phase`, `latest_recorded_event`, `journal_complete`, `sequence`, `current_sequence`, `section`, `rows`, `next_cursor`, preview/execution group counts and kept reasons, `confirmed_unlinked_artifacts`, `executable`, and bounds. Prepared policy contains root IDs/paths/identities, exact project registration digest, cutoffs, observation/expiry and explicit auxiliary retention semantics. Native should treat identity integers as opaque data; compare the string owner_instance_id and exact policy_digest.

Preview rows are **flat artifact rows** with resource kind/ID, root ID, relative path, directory flag and logical byte size. Effects add outcome, optional reason and logical bytes confirmed unlinked. Summary rows are empty; explicitly request preview/effects. Every cursor is HMAC-bound to owner-derived policy digest, operation, section and finite published sequence. An older cursor cannot expose an execution manifest before its publication sequence. Current executable=false after admission even on a historical preview page. Restart invalidates cursors, not durable operations; refresh without cursor.

## Durability and failure semantics

One stable global `retention.lifecycle.lock` is shared with updated CLI archive/restore/delete and legacy destructive prune entry points. Immediate contention is429; no blocking lock wait. The new executor acquires once and never calls a legacy prune beneath it. Existing compaction SessionLock remains inner and separate: it moves with the session and reacquires internally, so it cannot serve as the outer lifecycle lease. See `retention-lifecycle-lease.md` for coverage and non-Unix compatibility.

Prepared policy/preview and execution manifest are atomic-replaced private files under `<global>/maintenance/retention/<operation_id>/`; containing directories are synchronized. The append-only events file is synchronized before each possible destructive syscall and again after its outcome. It records monotonically sequenced accepted/executing/dispatching/outcome/terminal events. Appends use one held writer and do not rescan prior events per artifact. Receipt reads fold one bounded captured journal prefix with indexed artifact outcomes.

States: prepared, accepted, executing, complete, partial, refused, interrupted_unknown. A prepared cursor does not authorize a new operation after acceptance. A complete state means selected actions reached known terminal outcomes, not that every archived resource was deleted. `preview_kept`/`execution_kept` remain separate from selected artifacts.

Effects: `unlinked_confirmed`, `already_absent_observed`, `kept_changed`, `effect_unknown`, `not_attempted`. Removal errors are conservatively unknown because failure may follow unlink during parent-directory fsync; the executor stops all remaining work. Ownership recheck failure keeps the group and can yield partial. Scan/budget/root refusal after admission records zero-effects refused. A deadline stops at the next action checkpoint and preserves prior results. Per-kind filesystem/syscall failures are never folded into empty success.

A crash or journal write failure after dispatch but before the result preserves dispatching as unknown. A nonterminal receipt observed while the lifecycle lease is available is reported interrupted_unknown. The next execute returns the same receipt instead of resuming. Torn/invalid journal tails refuse all execution; GET retains the valid committed prefix, confirmed earlier effects and an explicit journal_complete=false/unknown state. A later absent file never retroactively proves this operation deleted it. No automatic journal garbage collection exists. Native must persist the known owner/policy/operation ID before POST and use Refresh Status after uncertain transport.

## Bounds and limits

Requests64KiB; selected plus explicitly kept groups256; materialized artifacts4096; directory entries50,000; aggregate metadata32MiB; single source metadata256KiB (project registration64KiB); complete manifest4MiB; each durable file/event journal8MiB; operation directories256; response1MiB with rows capped near512KiB,100 rows/page. Scan checkpoints stop after5s and execution checkpoints after30s. These are cooperative elapsed checkpoints, not deadlines on a hung filesystem syscall. A scan exceeding limits refuses the entire execution selection before effects; it never deletes an undisclosed firstN prefix. Data transcript bodies are not scanned. Bounds can keep large histories unavailable for destructive operations while legacy preview continues to work.

No transaction, rollback, physical disk-reclamation estimate or adversarial filesystem CAS is promised. Anchored no-follow descriptors confine path resolution. The advisory lease coordinates updated supported Rupu actors, not older binaries or arbitrary same-user writers. `stat`/unlink remains non-atomic against those actors. Active transcript/netflow writers and direct lower-helper calls are outside that lease coverage; positive archived ownership and conservative exclusions are required. Stream-only run directories are intentionally retained so unrelated RunStore lifecycle is not silently added to this protocol.
