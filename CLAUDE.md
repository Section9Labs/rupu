## Architecture rules (enforced)
1. **Hexagonal separation.** `rupu-providers`, `rupu-tools`, `rupu-auth` define traits (ports). The agent runtime in `rupu-agent` only knows traits.
2. **`rupu-cli` is thin.** Subcommands are arg parsing + delegation. No business logic in the CLI crate.
3. **Workspace deps only.** Versions pinned in root `Cargo.toml`; never in crate `Cargo.toml` files.
4. `#![deny(clippy::all)]` workspace-wide via `[workspace.lints]`. `unsafe_code` forbidden.

### Crates

- **`rupu-tools`** — the tool catalog, every production tool body, and the one permission path (specs `docs/superpowers/specs/2026-10-07-rupu-tool-and-launch-architecture/W1-tool-catalog-and-permissions.md`, `…/W4-mcp-as-transport.md`, `…/W5-flow-tools-into-catalog.md`). Every `Tool` returns a static `ToolDescriptor` (canonical `namespace.verb` name — core fs/shell tools stay unqualified — legacy `aliases`, one `Effect` = read/record/write/external/spawn, `needs: &[Service]` (services it can't run without — a grant checks these), `uses: &[Service]` (instrumentation it feeds when present: `read_file` → coverage, `bash` → netflow), description, schema fn). `catalog::ALL` lists every descriptor: the core fs/shell tools, the launch tools `dispatch` / `join` / `workflows.generate` (`launch/`, W7), `coverage.*` (`coverage/`), `findings.{report,verify,query,tag}` (`findings/`), `assets.mark` (`assets/`), the connector tools `scm.*` / `issues.*` / `github.*` / `gitlab.*` (`scm/`, `issues/`, `github/`, `gitlab/` — bodies take `ToolServices.scm`, errors are `connector::ConnectorError` text) the flow tools — `board.{claim,release,post,read,directive,retract}` (`board/`) and `msg.send` (`msg/`) over `ToolServices.message_bus` (a `rupu_fleet::Bus`: the author of a post or directive is the bus's participant, never a hardcoded `lead`), `agents.{list,get}` / `workflows.{list,get}` / `catalog.search` (`roster/`) over `ToolServices.catalog`, `goal.{status,coverage}` (`goal/`; `coverage.status` is a FlowLead-scoped alias) and `budget.status` (`budget/`) over `ToolServices.run_status` — each descriptor next to its body. The launch tools (spec `…/W7-unified-dispatch.md`) act through `ToolServices.launcher` (`ports::Launcher`: `check`, `launch(ChildRequest)` → `ChildHandle`, `join(JoinSet, timeout, Until)` → `ChildStatus`es, `finish(ParentEnd)`, `children`, and the continue-on-resume calls `continue_children` / `abandon_children` / `end_interrupted`) and `workflow_generator`: `dispatch` takes `kind` subagent|agent|workflow, is async unless `wait: true` (`join` for one handle); `MAX_LAUNCH_DEPTH` (5) is the one depth limit. The legacy names are byte-compatible alias shims picked by `CallContext.called_as` — `dispatch_agent` / `dispatch_agents_parallel` (sub-agents, waiting, the old output), agentiflow `dispatch` with a legacy `agent` field (kind agent, `{handle, participant}` inside a flow, `dispatch_agent` semantics outside one), `run_workflow`, `generate_workflow` (generate + dispatch) and the agentiflow `join` — pinned by `tests/fixtures/launch/` goldens; the model only ever sees the canonical names. `ports` holds the ports for effects that need a runtime above this crate: `CatalogPort` (`agents()` → `AgentEntry`s or the reason they couldn't be listed, `workflows()` → `WorkflowEntry`s; adapter `rupu_orchestrator::FsCatalog`) and `RunStatus` (`goals`/`coverage`/`budget` → `GoalReport`/`GoalCoverageReport`/`BudgetReport`, each with a `to_json` that builds the exact JSON the tool returns; implemented by `rupu_agentiflow::FlowStatus`) + `PortError`. `bodies::body(name, &ToolContext)` builds a run's tool and is `None` exactly when a needed service is missing — `ToolServices::provided(coverage)` is the same accounting, held in lockstep by `tests/it/descriptors.rs` (which also fails if a `Tool` impl lacks a catalog entry, an alias collides, or any crate implements `Tool` outside test code). The ledger tools derive where they write from the call's context (`ledger::{paths, tag_log, run_stream}`: the identity's findings scope in the workspace, mirrored to `services.coverage_stream`), so the same identity writes the same bytes through any transport; `coverage.*` read `services.coverage_catalog` (set by the agent loop). `findings.report` (aliases `report_finding`, `findings.record`) is the one findings implementation: its descriptor schema is `wide_schema()` (both profiles + the flat `rationale`/`code_excerpt`/`references` an `action:` step sends), an instance's `input_schema()` is its run profile's (`summary_schema()`/`full_schema()`, snapshot-pinned), and a flat-form call gets errors in that form's vocabulary. `call::call` is the one out-of-loop call path (`action:` steps and the CP's `/mcp`): `PermissionPolicy` on the effect, invoke, `CallOutcome::{Done, Denied, Failed}`. `ToolDescriptor::is_action_eligible` (not core, not `Spawn`, `needs ⊆ ACTION_SERVICES` = Scm + Findings) is which tools an `action:` step may call; `namespace()` feeds `/api/tools`. `permission::PermissionPolicy` (mode + optional `Prompter`) is the ONLY permission decision: `decide` reads the effect, never the name (readonly allows read/record, denies write/external, caps spawned children at readonly; ask prompts write/external or, with no prompter, allows them with a one-time `permission_mode_degraded` notice; "allow always" is per tool via `AllowAlways`); `PermissionMode::parse` is the one mode-word parser. A `Spawn` call carries its ceiling on `ToolContext.call.spawn_ceiling` (+ the run's `services.prompter`); `SpawnPermission::child_policy` gives a child `min(ceiling, its own permissionMode)`. `ToolContext` (W3, `tool.rs`) is `identity: Arc<RunIdentity>` (run id, codename, agent, the provider/model the run STARTED on, depth, `ParentLink { run_id, codename, root_run_id }`, `Surface` (agent/workflow/session/agentiflow; `coverage()` maps it), findings `scope_name` (`scope()` falls back to the agent), `step_id`, `launch: LaunchScope` (the agents/workflows it may launch — `(declared ∩ flow pool | declared | pool | nothing) ∩ the parent's cap` —, the flow `pool`, the `connector_cap` its children inherit, `children_dir`, its `usage_root` and, under a process child, the tree's `rollup_root`, the `flow` dir)) — set once by the run assembler, never written by the loop — + `workspace: WorkspaceScope { id, path, bash: BashConfig }` + `services: ToolServices` (launcher, workflow generator, SCM `Registry`, findings options, coverage writer/catalog/stream, netflow sink + capture, customer, prompter, `message_bus`, `run_status`, `catalog`) + `call: CallContext { tool_call_id, spawn_ceiling, called_as }`; `ToolContext::in_workspace` builds a bare one (tests, one-off tool calls). Skills (spec `docs/superpowers/specs/2026-10-12-rupu-agent-skills-design.md` §3): `skills.load` (`skills/`, `Effect::Read`, needs `Service::Skills`) re-reads a granted skill from disk (a moved or hidden one is refused, an edited one loads at its new version with `changed`); `ToolServices.skills` holds the run's `ResolvedSkills`, and `Service::Skills` is provided (so `AmbientGrant::skills()` offers the loader) only when one of them is model-loadable; `WorkspaceScope.read_roots` (every granted skill's canonical root) lets `read_file` / `grep` / `glob` / `ast_grep` read there (`path_scope::is_readable`, no coverage touch) while `write_file` / `edit_file` keep `is_inside`. `output::{ok, ok_json, failed, req_str, opt_str}` are the shared tool-output helpers. `bash` refuses `ToolCatalog::non_shell_names()` (every non-core dotted/underscored name and alias) as shell commands. `grant` (W2, spec `…/W2-tool-grants.md`) is the ONE grant resolver: a `ToolCatalog` value (the static list `.with(..)` a run's injected descriptors) resolves `GrantInputs` (agent `tools:` or `DEFAULT_GRANT`, step `actions:`, `AmbientGrant`s — `concerns()`, `engagement()`, the origin grants `flow_lead()` / `flow_unit()` (`origin:flow_lead` / `origin:flow_unit`, today's lead and unit toolsets; the lead's includes `dispatch` / `join` / `workflows.generate`) — the run's `ServiceSet`, `AliasScope`, and the `connector_cap` a launching parent passed down, which narrows connector tools like `actions:` and comes back as `ResolvedGrant.connector_cap`). D22: a descriptor with `wildcard: false` (the authority tools `board.directive` / `board.retract`) is never granted by `*` — only by its exact name, an alias, its `ns.*` or an origin/ambient grant (`star_parity_per_origin` in `rupu-runtime`'s `tests/it/assembly.rs` pins `*` under every origin); `board.retract` lifts only directives the caller authored into a `ResolvedGrant` (entries with `GrantReason`s, `narrowed`, `unavailable` → `tool_unavailable` notice, `skipped`). Grammar: exact / alias / `ns.*` / `core.*` / `*`; an unknown name is a `GrantError` with a did-you-mean (`validate_names` checks names only, at agent load). `actions:` narrows connector tools only (`needs` ∋ `Scm`, `ToolDescriptor::is_connector`); ambient grants (`concerns`, `engagement`) are never narrowed. Services are exact — `Launcher` for the launch tools, `WorkflowGenerator` for `workflows.generate`, `Engagement` for `assets.mark` — so a grant never offers a tool the run can't build. `DEFAULT_GRANT` is `core.*`, `dispatch`, `join` and the connector namespaces.
- **`rupu-agent`** — agent file format (`.md` + YAML frontmatter), agent loop, and permission-mode resolution (`resolve_mode`, the `PermissionPrompt` TTY UX). Lifts spec/loader/permission/runner/tool_registry into one integration crate. `AgentRunOpts` (W3 §3.5) is what the run assembler (`rupu_runtime::assembly`) builds: `system_prompt`, `prompt: UserTurn` (message, seed, seed source, turn offset), provider, limits, recovery, `permission: PermissionPolicy`, `grant: ResolvedGrant`, `alias_scope`, `tool_context` (the identity lives there: `opts.identity()`), `pins: AgentPins` (effort, thinking display, context window, output format/schema, `anthropic_*`), concerns, max turns, `stream: StreamOpts`, `hooks: Hooks` (`on_tool_call`, `on_usage`), pause, collectors, transcript path; the loop keeps the provider/model a fallback hop moves to in its own state, never in the identity. Production code never builds it by hand (`rupu-runtime`'s `no_hand_built_run_opts` test, no exceptions) and never calls `run_agent*` itself — only the assembler does. `record_unstarted_run` (+ `UnstartedRun`) writes the transcript of a run that never started (its agent did not load, its provider is undeclared or did not build) the way a run whose first call failed reads — `run_start`, the `model_limits` notice, seed/user turn, `turn_start`, then a `Preflight` close or an `Outcome` + close — and returns its `RunError`; it is what replaced the orchestrator's error-stub providers. `PermissionPolicy` decides every tool call from the resolved tool's descriptor (there is no decider trait); `ToolRegistry` is keyed by canonical name and resolves aliases, the transcript's `ToolCall` keeps the name the model used. Tool grants (W2): `grant::resolve_run_grant` resolves ONE `ResolvedGrant` from the agent's `tools:` + the step's `actions:` + ambient grants (`concerns:`, engagement, the origin's) + the parent's connector cap + the services the run's `ToolContext` provides (`ToolServices::provided`) at assembly (`grant::with_grant` for tests); the loop writes it as a `tool_grant` event (+ a `tool_unavailable` notice per named-but-unservable tool), and builds the registry in one loop over its entries (`rupu_tools::bodies::body`, after setting the flattened concern catalog on its context; a granted tool with no body is a `RunError::ToolGrant`, never a silent drop); it defines no tools and starts no MCP server (no `rupu-mcp` dependency); every call writes exactly one `tool_audit` (`decision` allowed / denied:* / not_granted, `reason`). `load_agent` (and `load_agent_admitted`) also checks `tools:` (`AgentSpec::validate_tools` → `AgentLoadError::UnknownTool`); `load_agents` / `find_agent` only parse (listings show the error per agent); `check_agent_files` backs `rupu agent validate`; `check_agent_skills` is its skill check on one agent, over a `SkillCatalogCache` a listing shares (a failed discovery included) — the CP's agent `load_error`. Mock-provider tests use `MockProvider` + `PermissionPolicy::bypass()`. Skills: `skills:` / `preloadSkills:` frontmatter, whose names `load_agent` checks against the skills directories' listings only (`rupu_skills::check_grant_names`; the run assembler resolves them in full, `rupu agent validate` too) (`AgentLoadError::Skill` over a typed `SkillCheckError`, its message naming where an unknown skill was looked for; a workflow step maps it to `AssembleError::Skills`; whose fd exhaustion `fd_budget::FdExhaustion` classifies so `retry_on_fd_exhaustion` retries it); after `tool_grant` the runner writes `skill_index`, a `skill_load { via: preload }` per preload (its resolve-time hash) and a `skill_not_indexed` notice per unloadable skill; a successful `skills.load` writes `skill_load { via: model }` plus `skill_changed` / `skill_tools_missing` notices. - **`rupu-launch`** — the one launcher (W7, spec `docs/superpowers/specs/2026-10-07-rupu-tool-and-launch-architecture/W7-unified-dispatch.md`): `RunLauncher` implements `rupu_tools::Launcher` + `WorkflowGenerator` for every child kind — `subagent` (a tokio task on the launcher's runtime, assembled as `Origin::SubAgent`), `agent` (`rupu run`) and `workflow` (`rupu workflow run --plain`), the process kinds spawned through W6's `RunArgv` with the parent's `LaunchLink` (`--launch-depth/-ceiling`, `--parent-run`, `--root-run`, `--usage-root`, `--launch-agents/-workflows/-actions`) via the `ProcessBackend` port (`Subprocess`; tests use `testing::ScriptedProcesses`). `LaunchEnv { assembler, store, events, namer, backend, runtime, max_concurrent, generation, project }`; `Launchers::local(global, &config)` is the `LauncherFactory` a workflow run builds its launcher from. Vetting (allowlist from `RunIdentity.launch`, `MAX_LAUNCH_DEPTH`, ceiling) happens before a child exists; a process child starts synchronously when a `[dispatch].max_concurrent_children` slot (default 8) is free, so "dispatched" means started, else it queues. Every child gets a codename from the parent's namer and lines in the parent's children ledger (`ledger.rs`: `<parent run dir>/children.jsonl`, fs2-locked append): `started` as it is launched, queued or not (handle, kind, name, run id, transcript, `request` — mode, `LaunchLink`, prompt, vetted workflow file, inputs — `continues` (the earlier run of the handle it continues), `prior_tokens`, `tree` (the dir of the launch tree's root run, from `rollup_root` / `usage_root`)), `spawned` for a process child (pid + `proc_start`, read in `Subprocess::spawn` before anything can reap it), `finished` (status, success, `output`, `cause`, tokens, duration; an `interrupted` end's `at` is when the stop was asked for, before any signal), `joined` when `join` first collects it, and `continued { handle, by_run }` when another run takes the handle on — that closes this ledger's record for good (`ChildEntry.continued_by`, `has_final_end`). A child ends once: a `finished` for a handle with a final end (or a second `interrupted`) is dropped under the lock; `interrupted` is the one end another may follow. `DispatchStarted`/`DispatchCompleted` executor events carry `kind`. `join`'s tokens are cumulative per handle: a child's own run's (`identity::tokens_of`: its usage ledger, an agent's transcript as a fallback) plus its earlier runs' (`prior_tokens`; a resumed workflow keeps one ledger, so nothing is added twice). `finish(ParentEnd)` stops what the parent never joined (process children SIGTERM'd, then killed after `TERM_GRACE`; a sub-agent dropped after its grace, or whose task panicked — settled `failed` by the task's watcher — has its own children finished too): recorded `abandoned` (`Stop::Abandon`: a workflow child's run is recorded `Cancelled`), or `interrupted` when it paused (`ParentEnd::Paused`, also the agent loop's mapping of a run in a terminating process) or its process is being stopped by a signal (`reaper::stopping`) — `Stop::Interrupt` leaves a workflow child's run as it stands, resumable, never looking like an operator's cancel. A process child that ended for good (anything but `interrupted`) has what it left below it abandoned (`reaper::abandon_below`). A child killed by a signal while its records say its run never ended reads `ProcState::Died`; it, or a `Failed` (a workflow runner that recorded the stop as it failed), is `interrupted` when this process is stopping, else `failed` — and a `failed` one whose own records carry a stop cause leaves what is below it to its parent's end (kept when the parent is stopped too, abandoned by `finish` when it ends for good). A signalled process (`rupu-cli`'s SIGTERM handler; SIGINT for `rupu run` / `rupu workflow run|resume`) stops every child its runs launched through `reaper::stop_live_children` (the launcher registers each ledger it writes) before it dies, recording each `interrupted` (D2), so continuing it continues them, at every level: each process child's own handler does the same for its children. It first sets the process-wide stop (`reaper::stop_token`, set under the exclusive side of `SPAWNING`, which every spawn holds shared from its gate check to its ledger lines): nothing spawns after it — `launch` refuses (`stopping`), a queued child settles `interrupted` — and it stops again until no unfinished child is left or the grace is spent (`reaper::reset_stopping` lifts it in tests). Identity (`identity.rs`): `Recorded::leader` is the only liveness check on a recorded pid — the pid's process must have started when the recorded one did (`proc::start_stamp`: Linux `/proc` stat, macOS libproc), compared before anything else; one recorded without a start time is never confirmed (never signalled, never read as running). `reaper::stop` signals only an unfinished child whose leader is `Live` (or an unreaped `Zombie`, whose group id is still reserved), or whose leader is `Gone` while a member of its group carries the child's run marker (`rupu_tools::RUN_ID_ENV` = `RUPU_RUN_ID=<run id>`, set by `Subprocess::spawn` on every process child and forwarded by `bash` whatever its allowlist; `proc::group_carries_env`: members by `/proc/*/stat` pgrp + exact `/proc/<pid>/environ` entry on Linux, `ps -A -o pid=,pgid=` + `ps -wwE` tokens on macOS, where the kernel hides Apple binaries' environments, so a group of only `/bin/sh`/`/bin/sleep` stays unverifiable; re-checked before the SIGKILL), never an unmarked leaderless group (logged, not signalled) and never a child already recorded `interrupted` or ended, and records every end before it signals. Whether a child's run ended is `identity::own_end` (an agent's transcript `run_complete`: a stop cause → unended, ok → done, error → failed, aborted/none → unended; a workflow's `run.json`: completed → done, cancelled/rejected → failed, failed → failed unless its typed cause is a stop or it failed at or after the stop that interrupted it, not found → never started). A stop cause is `rupu_transcript::StopCause` riding the run's typed cause as an `OutcomeRecord` class (`stopped_by_signal`: a workflow run that ends failed while `rupu_providers::credential_writes::stopped_by_signal()` — SIGTERM's `terminating()` or the SIGINT handler's `mark_sigint` — an agent's SIGTERM `aborted` close, and `RunError::cause` of any failure while that holds; `runner_died`: `RunStore::reap_if_orphaned`, i.e. `cp serve`'s sweep and `workflow resume`); `identity::own_stop` reads it, never a message. Continue-on-resume: `Launcher::continue_children(prior_run, ctx)` runs before the continuing run's first turn — the orchestrator's `dispatch_one` when a resumed step/unit attempt is seeded from the attempt it replaces (`replaced_attempts`, the latest row per unit in `attempts.jsonl`, read before the new row lands), `rupu run --continue`, and a continued sub-agent for its own prior sub-run. `reaper::interrupt_orphans` first records what a crashed attempt left unfinished: still running → stopped and `interrupted`; ended on its own records → that end; else `interrupted`. Then each entry not yet taken on is claimed under the prior ledger's lock (`ledger::claim`: a `claimed` line naming the run, the ledger it records the child in and its process; a live claim is left alone, a dead claimer's is closed for it when its ledger has the child, else taken over; `released` when not taken on), taken on under its handle in the new run's ledger and closed in the prior one (`continued`): ended ones restored as recorded (`joined` kept), except a `failed` one (joined or not) whose own records carry a stop cause (`own_stop`: the reboot race, where a child records its own end before its parent records the stop), which is continued like an interrupted one; interrupted ones by `own_end` / `prepare_continuation` — ended on their own → restored with that end (what they left below abandoned), never started (a queued child, or a process child stopped before its transcript / `run.json` existed) → launched afresh from the recorded `request` (D1; a continuation that never started retries the run it continued), otherwise continued (`agent`: `RunArgv::Agent` with `continue_from`, new run id, same codename; `workflow`: `WorkflowControl::Resume` of its own run, its `launch.json` rewritten with the bounded link first; `subagent`: `Origin::SubAgent` seeded by `apply_continuation`). A continued or relaunched child runs no wider than it was launched (`Caller::bounds`: the lower ceiling, the caps both links allow, the deeper depth, under the continuing parent's run/root/usage). A launch refused because this process is stopping leaves the prior entry as it was. A restarted attempt calls `Launcher::abandon_children(prior, "its run restarted")` (`reaper::abandon_unfinished`, recursive through each child's own ledger or, for a workflow child, its attempts'). `run_workflow` calls `Launcher::end_interrupted(run)` (`StepFactory::launcher`) whenever a run ends other than paused or by a signal, or an operator cancelled it (`reaper::end_interrupted_of`). `RunStore::cancel` records `Cancelled` before it SIGTERMs the runner, and the runner's signal path (`stop_live_children`, first) abandons, down the tree, what every cancelled run of this process launched (`reaper::abandon_cancelled_runs` over `runs::local_runner_dirs`): nothing continues a cancelled run. The orphan sweep (`reaper::reap_orphaned_children`) skips closed records and needs no lineage: a dead parent's unfinished child is recorded as `interrupt_orphans` would, and a child (orphaned or `interrupted`) is `abandoned`, with what is below it, only once nothing can continue it — an agentiflow's, or its parent's own run record (a `rupu run` writes one only at its end) or its `tree` root's says it ended (a workflow run that `failed` can still be resumed, so only its other terminal statuses count; a `rupu run` that failed of a stop cause can be continued, so it doesn't count either); a crashed standalone parent's children wait, `interrupted`, for `rupu run --continue`. `workflows.generate` (and dispatching what it wrote) allows a connector `action:` only when the caller's own grant offers that tool, narrowed or not (`LaunchScope.granted_connectors`, set by the assembler from the resolved grant). `generate` adapts the orchestrator's `generate_definition_with_provider` (`Generation::resolve` picks the provider, cached per `GenerationKey::of(caller identity)`). A named workflow child is passed the vetted file (`WorkflowRef::File`), the catalog id it was vetted and recorded as (`WorkflowRun.workflow_name`, hidden `--workflow-name`, which `rupu workflow run` sets as the workflow's name: run record and findings scope; a resume keeps the recorded name) and its minted codename (`--codename`, the root its steps are named under); a launched workflow refuses (`WorkflowRuntimeError`) a step agent outside its link's agents. `proc` (moved from rupu-agentiflow) is the process-group / liveness helpers. Every linear/`for_each` agent attempt is appended to the per-run `attempts.jsonl` ledger (`RunStore::append_attempt`/`read_attempts`, `AttemptRecord`) as it starts; `recovery::discover` plans each step/unit that has no recorded result as `Continue` (seed a new run from the interrupted transcript), `Recovered` (it had finished — its answer is the result, no model call) or `Restart` (flagged with a reason), asking `rupu_agent::continuation::prepare_continuation` what the transcript says, and falls back to deriving attempts from `events.jsonl` for runs that predate the ledger. A `success: true` unit checkpoint is settled; a missing or `success: false` one is judged from its transcript (a SIGTERM-aborted unit is continuable). Plans ride on `ResumeState.recovery`; the runner consumes them and emits `Event::AttemptResumed { mode: Continued | Recovered | Restarted }` (the CLI live view marks `↩ continued`/`↩ recovered`). `--restart-interrupted` skips discovery. A new step/unit attempt seeded from the attempt it replaces (a `Continue` plan or the paused-step seed) has `dispatch_one` call `Launcher::continue_children` for that attempt's agent run before its first turn; any other new attempt calls `abandon_children` (see `rupu-launch`). Still restart: `parallel`/`panel`/loop-member steps and remote (`host:`/`distribute:`) units; `resume_run` also reaps a `Running` run whose runner pid is dead before resuming it. Failures carry a typed `cause` (`rupu_transcript::OutcomeRecord`) next to their error string: on `StepResult` / `ItemResult`, the executor's step-failed and unit-failed events, and the persisted `RunRecord` / `StepResultRecord` / `ItemResultRecord` / `UnitCheckpoint`, all `#[serde(default, skip_serializing_if)]`; a remote unit's cause stays `None` on the coordinator, and a resumed run clears it. A placed unit attempt (placed step, fan-out unit, fallback retry; not `host: local`) is named in the workflow run's netflow roster (`<run dir>/netflow.units.jsonl`, `rupu_netflow::land::append_roster_line`) before dispatch, and the fleet dispatcher collects its netflow after every post-launch outcome (`collect_netflow`), turning a missing / partial / unavailable landing into a `StepWarning`. `Workflow.messaging` (absent | `true` | `false` | `{ tools: [...] }`, checked by `ToolCatalog::resolve_messaging` at parse: only `board.*` / `msg.*`) → `messaging_switch()` (a `MessagingSwitch`) → `StepRequest.messaging` → `Origin::WorkflowStep.messaging`: every agent step and unit gets the default messaging set, the tools named as `ambient:workflow_messaging`, or none (`false`, which its children inherit), and shares the run's `messages/` space (spec F1a §7, F1d). A placed unit gets its workflow's switch as `UnitDispatch.messaging` (`remote_unit_messaging`: off under `StepFactory::messaging_capped`, `DefaultStepFactory`'s link `no_messaging`, else `Workflow::messaging_switch` as is, a `{ tools }` list included).

8. Make targets: `macos-gen` / `macos-build` / `macos-test` / `macos-run` / `macos-release`. The app is deprecated and has no PR CI job (ci.yml's `macos-app` was removed); these targets only run locally.
9. **Mutations are pending-state, not optimistic.** `cp serve` runs are detached subprocesses (approve = marker file for a resume worker/sweep; cancel/pause travel by signal) — a mutation POST's 200 means *recorded*, not *done*. `PendingAction` tracks `idle | pending(since) | confirmed | failed` per `(entityID, verb)`; confirmation only comes from the run's status actually changing through Phase 2's live machinery (stream/firehose/refresh), never from the POST response alone.
10. **Firehose is orchestrator-run-scoped, by design.** Standalone agent runs never enter `RunStore` and so never appear on the firehose; the new-run pill and live status patching only ever cover orchestrator runs. Not a bug — don't build a workaround for it.
11. **Release lane (Phase 7, complete).** `make macos-release` (xcodegen + `xcodebuild -configuration Release`, version-stamped via `RUPU_RELEASE_VERSION`, hardened runtime on) + `scripts/package-app-dmg.sh` (hdiutil-based DMG). The `macos-app` job in `.github/workflows/release-app.yml` builds, signs (same imported Developer ID identity as the CLI job), notarizes, staples, and uploads `rupu-app-darwin-arm64.dmg`/`.zip`/`.sha256` onto the same release `release.yml` made for the `v*` tag. That workflow is triggered by `release.yml` completing successfully (not by the tag), and builds only when `apps/rupu-macos/`, `scripts/package-app-dmg.sh`, the `Makefile`, or the lane itself changed since the newest same-channel release that carries an app — so a CLI-only tag never runs, and can never be failed by, the app build. The app's version string lags the CLI's between app changes by design; `VersionGate.minimum` is the compatibility contract. No self-update mechanism (Sparkle/appcast) this phase; see the post-parity backlog doc above.

## Code standards
- Rust 2021, MSRV pinned in `rust-toolchain.toml`.
- Errors: `thiserror` for libraries; `anyhow` for the CLI binary (Plan 2).
- Async: `tokio`.
- Logging: `tracing` + `tracing-subscriber`.
- Disk: cargo never garbage-collects `target/`, and every worktree has its own — tens of GB a day each (macOS debug builds leak a full `.o` set per rebuild; each `-p`/`--workspace`/toolchain combination rebuilds every test binary under a new hash). The Claude Code hook in `.claude/settings.json` (`scripts/claude-hook-sweep-target.sh`) sweeps a session's own `target/` after its cargo/make runs (log: `target/.sweep.log`); `make sweep-targets` sweeps every worktree by hand (`ARGS=--dry-run` previews). Don't "fix" disk by sharing one `CARGO_TARGET_DIR` across worktrees — same-named path crates overwrite each other.
- Integration tests: ONE binary per crate — modules under `crates/<c>/tests/it/` (`main.rs` lists them), never a new top-level `tests/*.rs` (each is a binary linking the whole dep graph; `rupu-cli`'s `tests/it/test_layout.rs` fails on one). They share a process: env-mutating tests are `#[serial]`, and `rupu-cli` keeps env/cwd-mutating tests in a second binary, `tests/serial/`, every test holding its `ENV_LOCK`. Run one file with `cargo test -p <c> --test it <file>::`.
