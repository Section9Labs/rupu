## Architecture rules (enforced)
1. **Hexagonal separation.** `rupu-providers`, `rupu-tools`, `rupu-auth` define traits (ports). The agent runtime in `rupu-agent` only knows traits.
2. **`rupu-cli` is thin.** Subcommands are arg parsing + delegation. No business logic in the CLI crate.
3. **Workspace deps only.** Versions pinned in root `Cargo.toml`; never in crate `Cargo.toml` files.
4. `#![deny(clippy::all)]` workspace-wide via `[workspace.lints]`. `unsafe_code` forbidden.

### Crates

- **`rupu-agent`** — agent file format (`.md` + YAML frontmatter), agent loop, and permission resolver. Lifts spec/loader/permission/runner/tool_registry into one integration crate. Mock-provider tests use `MockProvider` + `BypassDecider` exposed from `runner`. `continuation` (spec `docs/superpowers/specs/2026-10-01-rupu-recover-on-interrupt-design.md`): `prepare_continuation` classifies a transcript (finished / resume / failed) and rebuilds it via `replay`; `apply_continuation` seeds a new run by reference with the continuation note; `runner::push_user_turn` merges a user turn into a trailing user message, and replay applies the same rule (lockstep). Behind `rupu run --continue`. Response outcomes (spec `docs/superpowers/specs/2026-10-01-rupu-response-outcomes-design.md`, operator doc `docs/response-outcomes.md`): `outcome` classifies every reply and provider error (`classify_response` / `classify_error` → `OutcomeClass`, with a severity), and `recovery` owns the ladder policy table, the budget constants, `RecoveryState`, and `RecoveryOpts` (the `fallbacks:` chain + a `HopBuilder`, which `rupu-runtime` implements); the runner writes `Outcome` / `Recovery` transcript events and returns `RunError::Outcome` (with its rung-3 hint) when the ladder runs out. `run_agent_full` returns a `RunExit` that keeps the conversation even on failure, which is what a session turn and `rupu run --continue <id> --model/--provider` on a failed run build on.
- **`rupu-app-canvas`** — pure-Rust view layer for rupu.app (Slice D). Walks a `rupu_orchestrator::Workflow` and emits a `Vec<GraphRow>` of structured cells (pipe / branch glyph / bullet / label / meta) for the git-graph view. Snapshot-tested with insta; no GPUI dep. consumed by `rupu-cli`'s workflow output (`cmd/workflow.rs`, `output/live_run.rs`).
- **`rupu-coverage`** — coverage ledgers + concern catalogs + the findings write path. `report/` owns the structured finding report (spec `docs/superpowers/specs/2026-09-29-rupu-finding-reports-design.md`): typed `FindingReport`, embedded draft-07 schema (`schema/finding_report.schema.json`, `rupu findings schema`) kept in lockstep with `validate_report` by `tests/it/report_schema_lockstep.rs`, `full`/`summary` `FindingProfile` (step → workflow defaults → agent `findingsProfile` → `full`), and the content-addressed artifact store (`<RUPU_HOME>/findings/artifacts`). `FindingReport::artifact_refs()` is every file a report references (`artifacts` + evidence-block files); use it, not `artifacts`, wherever "any referenced file" is meant. `ledger::stream` is the ledger write path (`append_record`; the async file-touch writer and the catalog snapshot go through `stream_json` / `stream_catalog`), mirrored to a run's `runs/<id>/coverage.jsonl` when `ToolContext.coverage_stream` is set (`rupu run` only); its lines are `begin`, `runs`, `files`, `concerns`, `findings`, `assets` (the engagement asset ledger) and `catalog`. `ledger::ingest::ingest_unit_stream` merges a remote unit's stream into the coordinator workspace: re-keyed by scope, deduplicated (findings by id, assets by occurrence, the other ledgers by record equality), with artifacts (and evidence-block files) rewritten to `external` + `host`. `tools::attach_report::attach_reports` (`rupu findings import`) is the only path that rewrites a finding line: under the sidecar `findings.jsonl.lock` (which every findings append in `append_record` takes), after a byte-for-byte backup, by atomic rename; everything else appends.
- **`rupu-findings-report`** — pure renderers (blocks → Markdown / self-contained HTML / Typst→PDF in-process with bundled fonts), numbering (`<PREFIX>-NNN` per project by severity → declared_at → id) and selection, shared by the CP (`GET /api/findings/:id/export`, `POST /api/findings/export`, the web export buttons/dialog) and `rupu findings export --to md|html|pdf` (`--to`, not the global `--format`). PDF is behind the default-on `pdf` cargo feature (forwarded by `rupu-cp` and `rupu-cli`; roughly +45–55 MB in a release binary); the prefix comes from `[findings].export_id_prefix` in the GLOBAL config only. The renderers read no files: `image` evidence blocks are embedded (HTML `data:` URI, PDF via the Typst world's in-memory `TypstDoc::files`, Markdown as a path reference) only through the caller's `Blobs` reader — the CP's `with_local_blobs` → `ArtifactStore::read_verified` (local `copied` blobs, verified, ≤ `MAX_EMBED_BYTES`, raster by magic bytes via `rupu_coverage::report::raster_image_type`); remote/external/missing files are named, never fetched. Docs: `docs/coverage.md#exporting-reports`. `import` is a best-effort Markdown → `FindingReport` parser behind `rupu findings import` (docs: `docs/coverage.md#importing-reports-written-before-the-full-profile`).
- **`rupu-cp`** — control-plane server. SSH-hosted transcripts are served through a lazy mirror (`docs/superpowers/specs/2026-09-04-rupu-ssh-lazy-transcript-mirror-design.md`): `host/transcript_paths.rs` (what a mirrored run claims + the `<global>/mirror/<host_id>/transcripts/<key>.jsonl` cache layout), `host/lazy_tail.rs` (one shared `tail -F` per open file), the SSH tail pump's terminal batched pull with `.complete` sidecars, and `/api/transcript{,/stream}?path=&host=&run=` (`run` required by the stream endpoint for a not-yet-mirrored remote path; optional on GET — absent falls back to the legacy `get_transcript` proxy; `partial: true` when the host could not be reached to finish collecting). Placed units launch under the coordinator-minted `UnitDispatch.run_id` so their PR #646 mirror path is known before dispatch. Tunnel/bucket hosts implement `local_transcript_path` / `ensure_transcript_feed` / `pull_transcript` to join. `AgentLaunchRequest.findings_profile` (a placed unit's step → workflow-default findings profile) is honoured by EVERY connector as `rupu run --findings-profile`; peers advertise the `agent.findings_profile` capability (HTTP `/api/host/info` `features`, tunnel `Hello.capabilities`, bucket `nodes/<worker>.json` markers) and a connector refuses a profile its peer didn't advertise — never a silent drop. An SSH remote advertises through the hidden `rupu __features` (`node::protocol::FeaturesReport`, the same `host_features()` list `/api/host/info` serves): the SSH `resume_run` sends ONE remote command (`host/ssh.rs` `resume_command`) that runs it and dispatches `workflow resume --if-unfinished` (refuse a run that finished since the request rather than retry it) only when it lists `workflow.resume_if_unfinished` — an older remote gets the bare command, logged, since its clap would reject the flag and the detached resume would fail without a trace. `POST /api/runs/:id/resume?host=` refuses a remote run that isn't `paused` (the status `get_run_from_host` shows) before asking the host, as the local branch does. Tunnel and bucket hosts have no resume path; an HTTP host's own resume worker builds its argv. Agent codenames: hand-mapped run/step/session/finding/event DTOs carry `codename` + `codename_derived` (true when derived on read for legacy records that predate stored codenames); the web only displays them and takes tints/badges from the generated `web/src/lib/codenamePalette.gen.ts` (`make cp-codename-palette`). Finding endpoints (`api/findings.rs`): list rows (`GET /api/findings`, and `GET /api/coverage/:target`'s `findings`) are slim — no `report` body, with a `report_summary` (owner, product, cwe, root_cause, chain, completeness n/11, has_poc, verification_status) on full-profile rows; `GET /api/findings/:id` returns the full record plus per-claim `evidence_status` (`current`/`changed`/`missing`/`unknown`, claim files hashed off the async runtime); `GET /api/findings/:id/artifacts/:sha256` serves only artifacts or evidence-block files the finding references (`FindingReport::artifact_refs`; copied blobs from the store; external local files opened once and hashed from that handle — 409 if changed, 404 if gone; a remote unit's artifacts, which `ingest_unit_stream` records `stored: external` with `host` set, are pulled from that host on first view: one shared, cancel-safe pull per blob, capped at the recorded size (refused unpulled when that is over the coordinator's own `[findings].artifact_max_bytes`) and verified by size + sha256 before it enters the coordinator's store, any failure a 404 `{"unavailable": reason}`), always `nosniff` + `Content-Security-Policy: sandbox`, text inline as `text/plain`, raster images (PNG/JPEG/GIF/WebP, by magic bytes) inline as `image/*`, everything else as an attachment. `HostConnector::pull_finding_artifact` (required) streams a host-store blob to a temp file: local copies, SSH runs the hidden `rupu __findings artifact`, HTTP streams `GET /api/findings/artifacts/:sha256` (`findings.artifact_blob`; not finding-scoped), tunnel streams `ArtifactPull`/`ArtifactChunk` frames (`findings.artifact_pull`), bucket reads `artifacts/<sha256>`, which the worker uploads at run end, before `finished` (a blob that still fails after 3 passes is logged and released — the coordinator reports it unavailable; coverage lines are held until they land); see `docs/coverage.md#downloading-artifacts`. The web artifact browser previews and downloads remote artifacts the same way. Report exports (`GET /api/findings/:id/export`, `POST /api/findings/export`) are served from `api/findings.rs` on top of `rupu-findings-report` (see the `rupu-findings-report` entry above). Load-time rules: `GET /api/hosts` serves each remote host's last probe from `host/probe_cache.rs` (fresh <15s; stale → served + one background refresh; >5 min or never probed → awaited) — never add a per-request SSH probe to a page-polled endpoint; `serve_on` prewarms the usage index on the blocking pool; a sealed run's claimed transcripts are memoized in `UsageIndex::claimed_paths`. Per-host web loading: the Activity tables, the Usage headline and ⌘K runs and sessions load one host at a time through the single-host `?host=<id>` paths — `web/src/lib/perHost/` (watermark merge + `PerHostListEngine`; every request bounded at 45 s, with an `AbortSignal` aborted on timeout and on dispose) and `web/src/lib/usage/useUsageData.ts` (`group_by` pinned to `model`) — over the probe-free `/api/hosts/registered`. Single-host list status codes (`api::runs::host_list_error`): 501 = the host can't serve the listing (`Unsupported`/`Invalid`; shown "unavailable"), 502 = every other connector failure, `NotFound` included (shown "offline"), 404 = only `resolve_host`'s unknown host id (host removed, slice dropped). `SshHostConnector` serves its listing commands through a 5 s single-flight `host::listing_cache::ListingCache`: every mutation clears it (`clear_on_drop`), a listing runs in a spawned task to completion even if every caller leaves and its fresh answer is cached unless a mutation cleared the cache meanwhile, it is capped at 60 s (then the task is dropped and its ssh child killed — `kill_on_drop`, listing path only), a panicking fetch fails every waiter. `is_ssh_transport_failure` (stderr markers; `RemoteOutput` has no exit code) separates a down SSH host (`Unreachable`, offline) from an old remote rupu (`Unsupported`, unavailable) in `list_runs`/`dashboard_summary`. `HostConnector::unit_coverage` (required) delivers a unit's coverage stream as `CoverageRead { bytes, complete }`: local reads the run's own `coverage.jsonl`, and SSH, tunnel and bucket read the coordinator's mirror of it (SSH tails it, and its terminal pull fetches it in the same ssh round trip as `usage.jsonl`, before the transcript catch-up, marking the copy complete with a `coverage.jsonl.complete` sidecar only when the host's `run.json` was terminal and the file's `cat` exited 0 (each section's trailer carries its status); tunnel via `ArtifactFile::Coverage` when `Welcome` advertises `mirror.coverage`; bucket via `coverage.NNNN.jsonl` results, which the poller orders by numeric seq), while HTTP GETs `/api/runs/:id/coverage` behind the `run.coverage_stream` feature. The fleet dispatcher turns a snapshot read (a poll error after the run was observed, the wall timeout) or an incomplete terminal read into `UnitCoverage::Partial`. The orchestrator's `ingest_remote_unit_coverage` merges what it returns on every post-launch outcome, BEFORE the unit's workspace-sync delta applies — the delta keeps its `.rupu/coverage/` unless a complete (non-`Partial`) stream merged with its begin line and no malformed line (`UnitDispatcher::strip_delta_coverage`, required, → `rupu_workspace::Delta::without_coverage`) — and turns anything that goes wrong, and any `Partial` stream, into an `Event::StepWarning` — never a failed unit.
- **`rupu-cli`** — the `rupu` binary. Thin clap dispatcher to the libraries. Fourteen subcommands: `init` / `run` / `agent` / `workflow` / `transcript` / `config` / `auth` / `models` / `repos` / `scm` / `issues` / `mcp` / `watch` / `update`. Releases publish `beta` (prerelease) + `stable` channels via CI (`.github/workflows/release.yml`, triggered by a `v*` tag push): `gh workflow run release-beta.yml` cuts a beta now (`-f force=true` even if nothing shipped changed since the last one), while stable is promoted from a soaked beta weekly by `release-stable.yml` rather than published directly; `rupu update` follows the configured `[update].channel` (default `stable`). **CI is a release gate, not a merge gate** (`docs/RELEASING.md#ci-is-a-release-gate-not-a-merge-gate`): PRs merge with no required checks and run no Rust CI (only PRs touching `.github/workflows/`, `docker/`, `rust-toolchain.toml`, `.cargo/`, `packaging/`, `scripts/` run their checks); `release-beta.yml` runs the full `ci.yml` suite once on `main`'s HEAD and tags only if it passed (batches that change no product — only `docs/`, root `*.md`, `.github/`, `scripts/`, crate `tests/` — skip; `-f force=true` overrides). Verify locally before merging; `gh workflow run ci.yml --ref <branch>` opts a branch into the full suite; a red release is fixed forward. `rupu cp serve` runs a background gate sweep (`cmd/cp.rs`, alongside the cron tick) that fires overdue gates' `on_timeout` routing (reject → runs the same `on_reject` cleanup chain the CLI reject path runs; approve → spawns a detached `workflow approve`) and reaps orphaned `Running`/`Pending` runs (dead recorded `runner_pid`) as `Failed` — gated by `[cp].gate_sweep_enabled` / `[cp].gate_sweep_interval_secs` (`rupu-config`'s `CpConfig`, default on / 60s); landed via docs/superpowers/plans/2026-07-23-rupu-gate-nodes-plan-4-notify-and-sweep.md.
- **`rupu-providers`** — LLM provider clients behind the `LlmProvider` port (lifted from phi-cell). A reply's outcome is typed, never a string: `Stop` (`stop.rs`: `StopReason` + `WireStop` — the provider's own wire value, or none — plus refusal / served-by detail, with a per-provider `map` table for each wire format); an error reply is an `ApiErrorBody` with a normalized `ErrorClass` (`reply_error.rs`) carried by `ProviderError::Reply`; `overflow.rs` owns the context-overflow message formats and parses the full text kept in `raw`, not the 500-char `message` preview. `ContentBlock::Unknown { provider, raw }` keeps an unrecognized reply block with its raw payload, and `ContentBlock::Fallback` carries Anthropic's server-side fallback marker; request builders drop `Unknown` always and `Fallback` for every provider but Anthropic. `local.rs` and `broker_client.rs` report honest provider ids. Spec: `docs/superpowers/specs/2026-10-01-rupu-response-outcomes-design.md`. Anthropic server-side fallback (`anthropic.rs`): on API-key auth only (never OAuth), for the exact model set in `supports_server_side_fallback` (`[1m]` stripped), a request carries the `server-side-fallback-2026-07-01` beta and `"fallbacks": "default"`, gated by `[recovery].server_side_fallback` through `ProviderConfig.anthropic_server_side_fallback`; a 400 naming `fallbacks` disables it for the client's life and surfaces `ProviderError::FallbackUnavailable`, which the runner retries once with a `server_side_fallback_disabled` notice. A reply the fallback served carries `Stop.served_by`.
- **`rupu-runtime`** — run-assembly layer shared by the CLI, orchestrator and CP: `provider_factory` (build a `Box<dyn LlmProvider>` from config + credentials) and `model_limits` (spec `docs/superpowers/specs/2026-09-30-rupu-model-limits-discovery-design.md`: `resolve` gives every run its model's input limit + output cap — agent frontmatter → `[[providers.X.models]]` → the provider's live model list (1h v2 cache at `<RUPU_HOME>/cache/models/<provider>.json`) → unknown, with provenance, announced as a `model_limits` transcript notice; `refresh`/`catalog` back `rupu models` and the CP's `ModelCatalog` port, `GET /api/models` + `POST /api/models/refresh`, Settings → Models tab). `ModelLimits`/`Limit`/`LimitSource` themselves live in `rupu-providers` next to `ModelInfo`. `hop_builder` is the production `HopBuilder` (`RuntimeHopBuilder`) and `recovery_opts`, which every launch site calls to turn the agent's `fallbacks:` (else `[recovery].fallbacks`) into `RecoveryOpts`: an unnamed chain entry resolves to the run's origin provider, the agent's `auth:` applies only to a hop on that origin provider, and a hop carries none of the agent's limit pins.
- **`rupu-codename`** — leaf crate for human codenames (`cobalt-harbor/heron#412>lynx#3`): frozen word lists + FNV-1a hashing (`crew_for`, `role_word`, `derive_legacy`), the `Codename` grammar, crew tint / role badge palette, and `CrewNamer`/`SharedNamer` (per-run role allocation + instance counters, persisted to `<run_dir>/codenames.json`). The orchestrator's `codenames::RunNaming` walks static slots; names are minted once and stored on records, `RunStart`, and executor events (`AgentStarted` carries codename · agent · provider · model). Word lists are FROZEN — golden tests pin them.
- **`rupu-transcript`** — the JSONL transcript event schema, writer and reader (leaf crate; reference `docs/transcript-schema.md`). `Event::Outcome` / `Event::Recovery` carry the typed `OutcomeRecord` / `RecoveryAction` (`outcome.rs`, with the shared one-line renderers `outcome_line` / `recovery_line`), `TurnEnd` carries a `StopRecord` and `discarded`, and `RunComplete.outcome` names the outcome a run failed on. Permission gating mirrors the six-builtin model: per-tool allowlist + per-mode (`ask` / `bypass` / `readonly`). Native SCM tool catalog (18 tools): `issues.{list,get,comments,comment,create,update_state}`, `scm.repos.*`, `scm.branches.*`, `scm.files.read`, `scm.prs.{list,get,diff,comment,create}`, `github.workflows_dispatch`, `gitlab.pipeline_trigger` — `issues.comments` reads a thread, oldest-first, GitHub only (added 2026-08-28), `issues.comment` writes to it; there is no native issue-label-write tool, and `issues.update_state` is open/closed only.
- **`rupu-orchestrator`** — workflow YAML parser + minijinja rendering + linear runner with pluggable `StepFactory`. Action-protocol allowlist validation lives here. **Executor module** (`crates/rupu-orchestrator/src/executor/`): `WorkflowExecutor` + `EventSink` traits + step-level `Event` enum. `InProcessExecutor` runs workflows in a tokio task and fans events through `InMemorySink` (broadcast for live subscribers) + `JsonlSink` (append-only `events.jsonl` next to the existing `run.json` / `step_results.jsonl`). `FileTailRunSource` is the disk-tail counterpart for runs the executor didn't start (CLI / cron / MCP). `rupu-cli` routes through this surface. `RunStore::list`/`load` (and the autoflow history's `list_recent*`, which stop at the first whole UTC day that fills `limit`) read through `rupu_runtime::file_cache::FileCache` — a process-wide parse cache re-validated by `stat` on every read (opens cost ~60× a stat on matt's Mac); keep new hot-path record readers on it rather than re-reading files per request. That plan also ships an affordance for a legacy inline `approval:` on an agent step: a dashed gate badge marker plus a `workflowGraph.convertInlineApprovalToGate` "Convert to gate node" button that lifts the approval onto a new standalone gate step inserted just before it; full auto-synthesis of a phantom gate node is deferred. Plan 4 (docs/superpowers/plans/2026-07-23-rupu-gate-nodes-plan-4-notify-and-sweep.md) closes the arc: a gate's `notify:` connector hooks fire best-effort right as it parks (before the `StepAwaitingApproval` emit, via the same `action_dispatcher`/`execute_action_step` Plan 2 wired in — never on auto-approve, never blocking the pause on a notify failure), and `RunStore::reap_if_orphaned` finalizes a `Running`/`Pending` run with a dead recorded `runner_pid` as `Failed` with a terminal event appended (closing the same "spins forever" class PR #501 fixed for the approval-timeout side). **The gate/action-node arc is now complete**: action steps execute, gates render + are authorable, notify hooks fire, and unattended timeout routing + orphan reaping run without an operator present. The run-detail graph shares the editor's per-kind palette unconditionally (kind-colored nodes + connectors, run status as a glyph/label/animation overlay) via `components/graph/kindBridge.ts` — the `[cp].workflow_editor_ui` gate was removed in Arc 3 (ISSUES.md I-30) when the classic renderers were deleted; landed per `docs/superpowers/plans/2026-07-23-rupu-run-graph-next-visuals.md`. **Gate decisions are path-scoped** (scheduler spec §7, operator rule 2026-10-01): `RunStore::approve_gate`/`reject_gate`/`request_resume_{approval,rejection}` record each decision in `RunRecord.gate_decisions` under the run lock, and exactly ONE runner applies them — `claim_runner` (live `runner_pid` + an in-process registry) hands a decision recorded while a runner executes to that runner (`OrchestratorRunResult.handed_off_to`), which picks it up mid-run (250ms poll) or in `finish_runner`'s locked re-check before it parks. `claim_runner` also refuses a run already finished on disk (`RunnerClaim::Finished` → `RunWorkflowError::RunAlreadyFinished`): a late resume never re-enters it. An operator's `workflow resume` retry of a failed/rejected/cancelled run flips it to `Running` first; `cp serve` spawns `workflow resume --if-unfinished`, which refuses a run that finished since its request instead of retrying it. Approve releases only that gate's path; reject (DAG runs only — a linear run's reject still finalizes it) prunes only what is reachable solely through the gate and runs its `on_reject` chain alongside; a still-parked sibling re-parks without re-firing `notify:`. A runner's final write goes through `finish_runner` against the on-disk record, never its own snapshot. **Recovery** (`recovery.rs`; spec `docs/superpowers/specs/2026-10-01-rupu-recover-on-interrupt-design.md`, plan `docs/superpowers/plans/2026-10-01-rupu-recover-on-interrupt-plan-2-local-resume.md`): `rupu workflow resume` continues what a dead runner left mid-flight instead of restarting it. Every linear/`for_each` agent attempt is appended to the per-run `attempts.jsonl` ledger (`RunStore::append_attempt`/`read_attempts`, `AttemptRecord`) as it starts; `recovery::discover` plans each step/unit that has no recorded result as `Continue` (seed a new run from the interrupted transcript), `Recovered` (it had finished — its answer is the result, no model call) or `Restart` (flagged with a reason), asking `rupu_agent::continuation::prepare_continuation` what the transcript says, and falls back to deriving attempts from `events.jsonl` for runs that predate the ledger. A `success: true` unit checkpoint is settled; a missing or `success: false` one is judged from its transcript (a SIGTERM-aborted unit is continuable). Plans ride on `ResumeState.recovery`; the runner consumes them and emits `Event::AttemptResumed { mode: Continued | Recovered | Restarted }` (the CLI live view marks `↩ continued`/`↩ recovered`). `--restart-interrupted` skips discovery. Still restart: `parallel`/`panel`/loop-member steps and remote (`host:`/`distribute:`) units; `resume_run` also reaps a `Running` run whose runner pid is dead before resuming it. Failures carry a typed `cause` (`rupu_transcript::OutcomeRecord`) next to their error string: on `StepResult` / `ItemResult`, the executor's step-failed and unit-failed events, and the persisted `RunRecord` / `StepResultRecord` / `ItemResultRecord` / `UnitCheckpoint`, all `#[serde(default, skip_serializing_if)]`; a remote unit's cause stays `None` on the coordinator, and a resumed run clears it.
- **`rupu-scm`** — SCM/issue-tracker connectors. `RepoConnector` + `IssueConnector` traits per spec §4c; per-platform impls under `connectors/<platform>/`. Plan 1 ships GitHub; Plan 2 adds GitLab + the embedded MCP server. GitLab connectors (repo/issues/extras + event poller) hold a `token::TokenSource`, never a frozen token string: an OAuth token within five minutes of expiry is refreshed before each request through `CredentialResolver::oauth_refresher` (store lock, persisted rotation; a failed refresh of a still-valid token falls back to it with a 30s retry backoff), a 401 is retried once with `TokenSource::replacement_for` (adopts a re-login), and every GitLab request sends `Authorization: Bearer` (`PRIVATE-TOKEN` rejects OAuth tokens). `clone_to` refuses a self-managed account (clone URLs hardcode gitlab.com). GitLab SSO logs in as glab's gitlab.com application (`rupu_auth::oauth::gitlab`), or `[scm.<account>].oauth_client_id` (required for self-managed); the login records `oauth_client_id`/`oauth_token_url` on the credential and `refresh_inner` honours them.

**Run-time samples:** live at `<repo>/.rupu/agents/` and `<repo>/.rupu/workflows/`. Running `rupu` from inside the rupu checkout exercises the same project-discovery code path end-users use in their own repos.

## Code standards
- Rust 2021, MSRV pinned in `rust-toolchain.toml`.
- Errors: `thiserror` for libraries; `anyhow` for the CLI binary (Plan 2).
- Async: `tokio`.
- Logging: `tracing` + `tracing-subscriber`.
- Disk: cargo never garbage-collects `target/`, and every worktree has its own — tens of GB a day each (macOS debug builds leak a full `.o` set per rebuild; each `-p`/`--workspace`/toolchain combination rebuilds every test binary under a new hash). The Claude Code hook in `.claude/settings.json` (`scripts/claude-hook-sweep-target.sh`) sweeps a session's own `target/` after its cargo/make runs (log: `target/.sweep.log`); `make sweep-targets` sweeps every worktree by hand (`ARGS=--dry-run` previews). Don't "fix" disk by sharing one `CARGO_TARGET_DIR` across worktrees — same-named path crates overwrite each other.
- Integration tests: ONE binary per crate — modules under `crates/<c>/tests/it/` (`main.rs` lists them), never a new top-level `tests/*.rs` (each is a binary linking the whole dep graph; `rupu-cli`'s `tests/it/test_layout.rs` fails on one). They share a process: env-mutating tests are `#[serial]`, and `rupu-cli` keeps env/cwd-mutating tests in a second binary, `tests/serial/`, every test holding its `ENV_LOCK`. Run one file with `cargo test -p <c> --test it <file>::`.
